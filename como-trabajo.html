Cómo trabajo

Cómo encaro un encargo, por fases, y qué entrego en cada una.

De dónde viene mi método

Mi método salió de dos negocios de mi familia: una tienda de zapatillas y una empresa de transporte. En los dos vi lo mismo: el trabajo funcionaba, pero vivía en papeles, cuadernos y un Excel que solo una persona entendía. Primero aprendí cómo se hacía el trabajo; recién después pensé en un sistema.

En AYBIZ, por ejemplo, las reglas del sistema no salieron de mi cabeza: salieron del formato de cierre de caja de la agencia y de la liquidación de viaje del chofer. Un sistema que reemplaza unos formatos tiene que respetar lo que esos formatos ya resolvían.

Mi proceso, paso a paso

  1. 1

    Observar el trabajo real. Cómo se registran hoy las ventas, la carga, la caja.

  2. 2

    Identificar qué duele. Dónde se anota dos veces, dónde se pierde plata, qué no se sabe a tiempo.

  3. 3

    Definir el alcance. Qué entra en la primera versión y qué queda fuera, por escrito.

  4. 4

    Diseñar la base de datos primero. Las reglas del negocio van ahí; la pantalla solo las muestra.

  5. 5

    Construir una primera versión. Las funciones centrales, sin adornos.

  6. 6

    Probar con datos ficticios. Buscar los errores sin tocar la información real.

  7. 7

    Probar en el negocio. Un piloto con carga y caja reales, mirando cómo se comporta en el día a día.

  8. 8

    Ajustar con quien lo usa. Lo que el chofer o el cajero no entiende, se cambia.

Qué entrego en cada fase

Resultado de cada etapa del trabajo
Fase Qué recibe quien me encarga el trabajo
ObservaciónUn resumen de cómo funciona hoy el negocio y de los problemas que encontré.
DefiniciónLa lista de funciones acordadas y lo que queda fuera del alcance.
ConstrucciónUna primera versión que se puede abrir, probar y comentar.
PruebasLa versión revisada con datos ficticios y los errores corregidos.
Puesta en usoEl sistema trabajando con información real y las observaciones atendidas.

Principios que aplico

Decir lo que el sistema no hace
Prefiero declarar un límite antes que dejar que alguien suponga una función que no existe.
Nada se borra
Lo que ya se cobró no se toca: se cierra y se abre otra versión. Siempre queda el rastro.
En el idioma del negocio
Las pantallas, los mensajes y hasta el código en castellano, para que lo mantenga alguien de acá.
Cuidado con los datos
Pruebo con datos ficticios y no publico información de clientes reales.

Herramientas que uso

  • React con Vite y Tailwind CSS para las interfaces.
  • Supabase, que es PostgreSQL con usuarios y permisos, como base de datos.
  • Cloudflare Pages y Netlify para publicar.
  • Git y GitHub para las versiones.
  • HTML, CSS y Bootstrap para sitios informativos como este portafolio.
